A Memory
That Outlives the Session

01

Ruled a memory, not a transcript

August 2026: the store outlives the session

On 29 August 2026 the operator ruled that the organism's memory is a persistent, organized store — not a chat transcript. The record calls it the ruled memory substrate: a visual window over files, folders and links.

A transcript dies when the session ends. The store does not: a dated entry waits there for the next hand, and the next, and the one after that. Nothing here claims the memory is complete or undamaged; it is what the hands put into it, one entry at a time.

The gate outranks every write

Every write passes a gate before it is committed: a scan for anything that should not be written down, a size and format check, and a rule that a handful of foundational files can never be silently rewritten. If the gate finds a problem, the entry still exists on disk — only the receipt is withheld.

02

Every hand writes, nobody waits for a clock

No scheduler, no clock — decision points only

There is no scheduler and no clock inside the memory. Each hand writes at its own meaningful moments — when a job fails, when it recovers, when a session ends — never on a timer. Four hands are wired this way.

Each reads the memory's working-set summary before it acts, and writes a dated entry when it finishes. The summary stays short on purpose: a brief for the start of a session, never the whole archive.

03

Written is not the same as known

The line between a journal line and a claim you can rely on

A dated entry in the daily journal is not treated as settled fact. It has to be promoted into the knowledge folder through a review before anything relies on it. The same rule states the corollary: raw operational logs stay outside the memory entirely — only events judged worth a line come in.

Written is a line on disk. Known is a promoted claim. The two are not the same, and the memory never pretends they are.

      What stays outside the memory

      Deliberate boundaries, not gaps

      Deeper search over the memory — meaning-based, not just keyword — is opt-in and has to be asked for explicitly; it does not run by default on every write. A single machine's working-memory summary for any hand is capped at a small, fixed size on purpose, so what loads at the start of a session stays a short brief, not the whole archive.

      Raw operational logs, embeddings and private working notes stay outside on purpose. The memory is what the hands judged worth a line — nothing more, nothing automated beyond the five rules above.
