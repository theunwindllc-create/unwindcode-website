The Quotation Cell

A quote is not a form submission. It is a governed transaction packet: customer intent, line items, supplier options, pricing evidence, recommendation state, correction history, and human approval before commitment.

June 7, 2026 Domain Cell Manual Brain build record human approval before commitment
01 / Brain decision

The next domain cell is quoting.

The ecosystem is moving from static CPQ screens toward agentic quoting: systems that collect context, prepare options, route approvals, and connect quote-to-cash work. The Unwind Brain's response is narrower and safer: a Quotation Cell that can prepare a quote package, preserve evidence, and show readiness without pretending that preparation equals authority.

The Brain is not being represented as an unattended publisher here. Until the live Brain can run this loop directly, Unwind runs the Brain protocol manually against real signals: observe the movement, decide whether it matters, shape the organism pattern, write the public memory, verify the proof surface, and only then publish.

This transmission does not name a private business or active implementation. The public lesson is the cell shape: how a domain organism turns messy intake into reviewable work while keeping pricing, availability, purchasing, fulfillment, and final commitment behind human gates.

Signal

Agentic quote-to-cash

Quoting is becoming a conversational workflow with catalog, pricing, approval, document, and handoff state.

Rule

Quote package before commitment

The organism may prepare, revise, compare, and recommend. It does not finalize commercial consequence alone.

Decision

Publish the Quotation Cell

The user-facing proof surface is a command interface backed by quote-package state, supplier memory, trust events, and approval gates.

02 / Manual Brain run

Before the Brain turns on, the discipline still has to exist.

The manual run is not theater. It is rehearsal with real data. The page is written as if the Brain were maintaining its own continuity because that is the contract the runtime will later inherit: source signal, decision, architecture implication, approval boundary, proof artifact, and next-cell memory.

This is why the transmission has to read like a whitepaper. A future Brain should be able to return to the page and understand what was learned, what was intentionally not claimed, and what the next build should make visible.

03 / Cell map

The frontend is the command surface. The backend is the quote organ.

The user should be able to talk naturally: ask for a quote, change sizes, add constraints, correct quantities, compare options, and ask what is missing. Behind that exchange, the cell builds a structured package that can be inspected before it becomes operational.

Intake

Start with stated need.

The cell captures requested items, quantities, sizes, delivery context, constraints, and missing fields before any option is recommended.

Memory

Remember the supply side.

Supplier options, price snapshots, substitutions, availability notes, and confidence labels become evidence instead of hidden guesses.

Readiness

Make uncertainty visible.

The package marks what is known, what changed, what needs review, and why it is or is not ready for a human to send forward.

Handoff

Prepare, route, wait.

The organism can draft the package and route it. Pricing confirmation, purchasing, fulfillment, and commitment stay approval-gated.

04 / Organism build recipe

Build the quote organism as a state machine before it becomes an agent.

The mistake would be to start with a chat box and call it automation. A serious Quotation Cell starts with inspectable state. The agent can help collect, revise, compare, and explain, but the organism has to know which fields are settled, which evidence is fresh, which assumptions changed, and which actions still require approval.

1. Command surface

Create a buyer-facing or operator-facing interface where the user can ask, correct, compare, and inspect missing information without learning internal form structure.

2. Quote package schema

Model customer intent, line items, constraints, supplier candidates, evidence snapshots, confidence labels, correction history, readiness state, and review owner.

3. Supplier memory

Store source, timestamp, substitution logic, known limits, and stale-data warnings so recommendations are grounded rather than improvised.

4. Correction reducer

When a user changes quantity, size, delivery condition, or constraint, update the affected fields while preserving the trail of what changed and why.

5. Readiness gate

Separate internal intelligence, human-review-ready draft, supplier-check-needed package, and approval-required commitment paths.

6. Approval receipt

Record who reviewed the package, what evidence was visible, what remained uncertain, and what action the human allowed the system to take.

05 / Correction loop

The latest explicit signal wins.

A serious quote agent has to survive correction. When the user changes a size, quantity, delivery condition, or product constraint, the organism should update the package without losing the prior trail. That is memory with accountability: not a transcript dump, but a live state that explains what changed.

01

Capture

Record the latest request and the exact field it changed.

02

Reprice

Refresh affected lines, supplier options, and availability notes without touching unrelated context.

03

Explain

Show the reason, confidence, missing information, and review state attached to the updated package.

04

Approve

A human reviews before the package becomes an external quote, purchase path, or fulfillment instruction.

06 / Readiness meter

Transaction readiness is an approval boundary, not a vibe.

The quote package should be able to say what it is ready for. Some work is safe as internal intelligence. Some work is ready for human review. Very little should be treated as ready for commitment without explicit approval.

Readiness Boundary by Work Type

Lower bars can stay inside the organism. Higher bars need stronger review before consequence.

  • Capture need 20 Low-authority intake state.
  • Compare options 32 Evidence-attached review support.
  • Draft package 48 Human-reviewed quote copy.
  • Route review 72 Pricing and supplier checks rise.
  • Commit 100 Human approval before consequence.
07 / Boundary cards

The public claim has to stop before the purchase order.

The Quotation Cell is not a legal authority, payment processor, procurement system, supplier of record, fulfillment engine, or promise of price and availability. It is a governed intelligence layer for preparing reviewable quote packages.

What it can do

Capture intake, preserve corrections, compare supplier options, draft quote packages, mark readiness, and route human review.

What it must not imply

No promise of price, available supply, unattended purchase, fulfillment, legal status, or final commercial outcome is claimed by the cell.

What happens next

The next proof should make the readiness state inspectable: what changed, what evidence supports it, what is blocked, and who approved the handoff.
