TRANSMISSION 038

One Board
for Every Hand

On 8 November 2026 the operator asked for a rail so every agent could know what every other hand is working on, until a job board exists. The same day, one file became the interim job board for every hand.

November 2026·Field note·Coordination·7 min read

Dated note. This note describes 8 November 2026, the day the interim board opened, and was written and published the same day. Operational facts describe that day, not today.

Correction, 10 November 2026. An earlier version of this page described the free-model hand as running on a model on the machine with nothing off the box. That was incomplete. Only the calendar truth pass described below ran on the local model. The free-model hand can run on either a local model (nothing leaves the machine; its window is a hard 32,768 tokens) or a free cloud model (the brief leaves the machine, so only public-safe material may be sent to it; a rule for that is proposed, not yet ruled). The page itself was not written locally: Transmissions 38 to 55 were drafted by a free cloud-hosted model from briefs of public-safe facts. Revised 10 November 2026: the four hands are now named by role, and the order note in section 04 was corrected to match the clock.

01

A rail before the job board

One file, every hand, before the job board exists

On 8 November 2026 the operator asked for a rail so every agent could know what every other hand is working on, until a job board exists. The same day, one file became the interim job board for every hand: a terminal coding hand, a desktop coding hand, a free-model hand and a shelved hand. It is copied into the working-memory packet each hand loads when it starts, so every hand sees the open jobs before it acts.

The rules: claim before you start — one hand per job, with a timestamp. Finish with DONE plus a receipt, or hand back with a one-line note. A claim older than 24 hours with no note may be reclaimed. Every claim, finish and handoff is journaled. Jobs that wait on the operator cannot be claimed. The board grants no authority: a job permits only what its plan already marks lawful.

Above the board: the custody boundary

No private keys on the machine. No autonomous financial execution. It outranks every instruction, including automation. A job on the rail is permission for only what its plan already marks lawful now.

02

Four hands, one list

The board rides in the packet each hand loads at start

The board is copied into the working-memory packet each hand loads when it starts, so every hand sees the open jobs before it acts. The hands are a terminal coding hand, a desktop coding hand, a free-model hand and a fourth hand that is shelved for now. Select a hand to see what it does.

03

The prompt that did not fit

32,768 tokens · default agent · rail agent

The default coding agent sent about 39,000 tokens of prompt before doing anything — 45 video-editor tool definitions and a list of 29 skills. That is more than the local model's 32,768-token window. The lean rail agent keeps the rules and only file and shell tools: about 14,000 tokens, leaving about 18,000 for the job. Measured without loading a model, by pointing the agent at a dummy endpoint that recorded the request.

      04

      The day, as it ran

      Five steps · in the order they ran

      The steps are grouped by topic. By the clock, the memory squeeze (16:10 to 16:37) overlapped the calendar pass (proposed at 16:28), the lean agent and the two repairs were recorded at 16:40, and the push ruling came at 17:14.

      01

      The calendar truth pass

      The first job the free local model ran was the calendar pass: four rows proposed for the week's work that had none, and stale rows flagged but not changed. A second hand verified it — four rows added as proposed, zero existing rows changed.

      02

      The prompt that did not fit

      The default coding agent sent about 39,000 tokens before doing anything — 45 video-editor tool definitions and 29 skills — more than the local model's 32,768-token window. A lean rail agent, rules plus file and shell tools only, runs about 14,000 tokens, leaving about 18,000 for the job.

      03

      Two defects surfaced

      A configuration line with invalid escapes, there since August, had kept one agent version from starting. The shared rules file's first 4,096 bytes had been zeroed since an incident on 3 November; it was rebuilt byte-exact from a copy recorded on 27 October — every surviving byte matched, the rebuilt head came to exactly 4,096 bytes, the whole file to its recorded 12,070 bytes, and the damaged copy was kept so the restore can be undone.

      04

      The memory lesson

      With the local model loaded beside an idle video editor, memory reached 98% and the page file grew until free disk fell to about 3 GB. Clearing the editor's caches closed it; nothing was lost and disk recovered. Close the editor before loading the model.

      05

      Always push

      The operator ruled that nothing stays only on the machine. Every commit leaves at the task boundary through a custody gate that scans every outgoing file for secrets; the first push scanned 1,602 files and found none.

      05

      Not done, on purpose

      What waits, and why it is not built yet

      Nothing on this rail is built until the hand that owns it says so. The consolidation plan waits for the operator's approval; the receipt envelope, the vault repair, the editing department and the remote console open only after it. The rail itself is interim: the real job board will be the calendar plus a dispatcher plus an agent registry.

      06

      What actually changed

      The operator's ruling, one line each from the day

      The operator ruled "always push": nothing stays only on the machine. One line each from the day: the calendar pass proposed four rows and changed none; the prompt was measured — default agent about 39,000 tokens against a 32,768-token window, rail agent about 14,000; two defects surfaced and were repaired — an invalid-escape line from August and a zeroed 4,096-byte head rebuilt byte-exact to 12,070 bytes.
