A Board,
Not a Prompt

November 2026·Field note·Coordination·6 min read
01

One file, read before anything else

The whole mechanism, in one file

A single shared file, created on 8 November 2026 on a stated need: so every hand on the machine can know what the others are working on, until a more permanent job board exists. Every hand loads it into its working memory before it starts a session, so each hand sees the open work before acting. That is the whole mechanism — one file, read first.

02

Claim it, finish it, or hand it back

The rules live beside the jobs

The rules live in the same file as the jobs: claim a job with a timestamp before starting it, one hand per job; finish with a result and a reference to what was produced, or hand it back with a one-line note on what is done and what is left; a claim older than 24 hours with no note may be reclaimed by another hand; every claim, finish and handoff is logged; a job waiting on a human decision cannot be claimed by a hand; and the board itself grants no authority — a job listed here permits only what that job's own plan already allows.

03

More than one hand, the same day

More than one kind of hand, the same day

Within the same day the board went live, more than one kind of hand worked from it — for the first time, a free local-model agent finishing a job independently of the subscription-based coding agent that had been doing most of the work until then. One file, more than one hand, the same day.

04

Interim, and it says so

Interim by its own words

The board states its own limits plainly. It is explicitly interim, and the planned replacement is a calendar plus a dispatcher plus an agent registry — a more structured system this file is a stand-in for, not a competitor to.

04

A stand-in for the real system

It names its replacement — a calendar, a dispatcher and an agent registry — and calls itself a stand-in, not a competitor.

05

Why a record beats a retelling

An outlook, not a receipt

Outlook — this note's own reasoning, not a measured fact: a shared, journaled record plausibly coordinates better than a private prompt as more hands join, because each new hand only has to read one file to know the current state of the work, where private-prompt coordination requires someone to keep remembering and re-explaining what every other hand is doing. This organism has only tested that claim for one day, with a handful of hands, on one file. It is a reasoned expectation here, not a proven law.
