TRANSMISSION 001

The Entropy
of Agents

A March 2026 note argued that long agent sessions decay and that file-system geography would stop it. Eight months on, the decay is a real design problem, the geography cure was a phrase that was never tested, and what actually holds the line is smaller, stricter and written in code.

November 2026·Revised note·Agent memory·9 min read
Dated. This note describes the Brain and First Body as the record stands on 10 November 2026. The note it replaces was a concept piece published in March 2026.

Revised 10 November 2026

Rewritten to the Transmission standard. Every sentence of the March note was checked against code, tests, rulings and journals. Three claims are withdrawn and two softened, and the page now says what exists: a budgeted context packet, a canonical status file, schema-checked tool outputs, a fail-closed content guard and confined writes for generated code.

Correction, 10 November 2026

The March note said that mapped file constraints "halt the decay" and let digital minds "scale indefinitely", and it described agents writing database queries inside interface code as something witnessed. The record supports none of these. No measurement of drift exists in the repository, before or after any layout. The phrase "spatial determinism" appears in the project's white paper as one abstract sentence, and we found no definition or test of it. Those sentences are withdrawn.

01

Ten claims from March, checked

The ledger of what the old note said

In March 2026 this page made a clean argument. A language model starts a session brilliant and ends it confused. The cause is the context window, not malice. The cure, it said, was Spatial Determinism: program the model through the geography of the file system, so that "database layer" means a folder instead of an idea. Mapped file constraints would create "artificial gravity", halt the decay, and let digital minds scale indefinitely.

It is a good story. This revision asks what the record can show for each sentence. We broke the note into ten claims and marked each one: supported by a record, a design that is not proven, a metaphor, softened to what we can show, or withdrawn. Filter the ledger, and open a card to read why.

Two things to know first. None of the ten rests on a measurement of drift in our own sessions, because none exists. And the one line most worth keeping from the March note is a metaphor: "stop giving the AI instructions to read, and start giving it a physical space to inhabit." Section 02 shows what that became in code.

The tally: two claims supported, one a design, two metaphors, two softened, three withdrawn. The supported ones are the plain ones. The ambitious ones are the ones that fell.

02

What actually holds the line

Five controls, each with a trail

If geography is not the cure, what is? Five things hold on the record. None of them depends on the model remembering anything, and that is the point they share.

One place for current truth. The Brain's status file says at its top that it is canonical, overwritten and never appended, and that it wins over any older document that conflicts with it. The structure map is a curated map kept short, and it says it is not a ledger. This is the plainest anti-drift rule in the repository: one place for what is true now, and a rule for which document wins.

A budgeted memory. What a turn may see is decided by code, not by whatever is still in the window. Section 03 shows it.

Outputs that must fit a shape. A tool's output reaches a model only after strict validation, inside an envelope that names its source and marks it untrusted. After that, a guard reads it, and every kind of doubt ends the run instead of letting the text through.

Rules enforced where the action passes. The agent's operating rules say that untrusted text is quoted and never obeyed, and that approval of one call is never approval of the next. A gate enforces both, so the agent does not need to remember them.

Location as law. The one place where the March idea is literally true: generated code can be written into one folder only, and a file there runs only if a hash manifest lists it.

Mind the dates. The tool-output and guard entries come from the status file's September records, with the tests named there. They were not re-run for this note. The memory packet suite was, and it passed.

03

A packet with a budget

Toy numbers, real rules

The read side of memory builds a packet for one turn. It fills a small always-on block first, with the standing laws at the head of it, under a budget of 1,200 tokens. Then it adds up to 1,500 tokens of retrieved material, in a fixed order: unresolved items, then items linked to an active goal, then the best semantic matches, then the newest rows. Greetings and one-word replies skip recall entirely. Rows marked sensitive are excluded unless the caller opts in. Every recalled line carries its identifier, type and stage, so a reader can see where it came from.

The rule worth pausing on is what happens at the edge. A row that does not fit is skipped and counted, never trimmed, and a smaller row later in the order may still land. The six rows below are invented sizes chosen to show that rule; the budgets and the order are the design's. Drag the budget and watch which rows are skipped.

Nothing on this path calls a model. A test replaces the network layer with one that raises, and a full packet still builds. The token estimate is declared as an estimate: roughly one token per four characters, with no tokenizer download.

    A model of the packet rule, with invented row sizes. Not a trace of a real turn.

    04

    A rule in a prompt, a rule in a gate

    A model, not a measurement

    The March note was right that a rule written once at the top of a long session is fragile. Its remedy was to move the rule into the layout. The record's remedy is to move it into the place where the action passes. The two columns below are a model of the difference between those designs. They are not a benchmark of either.

    Pick a situation and read down both columns. A short session shows no difference, which is why the weakness is easy to miss. A long session erodes the first design and leaves the second untouched, because the second never relied on the window. The last situation matters most: text from outside that tells the agent to drop its rules. In the operating rules that text is data, and the gate is what makes the sentence true.

        05

        The record, in dates

        What happened when

        A page about drift should keep its own dates straight. Here is the sequence the claims above rest on, from the March note to this revision. Each entry names its source in the sentence, and where a figure is old, it says so.

        01

        March 2026 · The concept note

        Published as a whitepaper-style note. It proposed spatial determinism and named the problem agentic entropy.

        02

        25 to 28 May 2026 · Geography becomes law

        The first approved generated cell was activated through a hash manifest on 25 May. The 28 May hardening record lists confined writes and the manifest quarantine as verified.

        03

        5 September 2026 · A budgeted packet

        The memory read path was written and tested: no model call, two token budgets, a fixed order. Twenty-six tests that day; twenty-eight when re-run on 10 November.

        04

        6 and 7 September 2026 · Output meets a gate

        Tool outputs became schema-only, then a content guard that fails closed. With no guard serving, the record states the tool lane was closed until a hand served one; a 30 September entry records a guard serving as a local service.

        05

        8 November 2026 · The registry drifted

        An audit counted eighty-seven agent rows, fourteen of them real. Documents had said more than receipts could show. Progress now counts only from receipts, ledgers and files.

        06

        10 November 2026 · This note

        Rewritten with a claim ledger. A real measurement of drift on real sessions would be the honest next step; no such measurement exists in the record.

        The pattern in the timeline is that every control arrived after something went wrong or after a rule was written down, and none arrived because the layout of a folder had been declared a cure.

        06

        What this note does not claim

        Boundary
        • It does not claim that any file layout reduces drift. No measurement exists either way.
        • It does not claim that models fail at a particular session length. The twentieth prompt was an illustration.
        • It does not claim the five controls are complete. The record shows at least three failures that surprised us: a generator that bred near-copies, a truncation that made valid input wrong, and a registry that outgrew its receipts.
        • It does not claim the September tool-output and guard figures hold today. They are dated records and were not re-run for this note.
        • It does not claim any model remembers anything by itself. The memory is in the store and the rules, not in the model.
        • It does not claim entropy is measured. It is a name for a problem.

        The next honest step would be to measure drift on real sessions, with and without each control. That has not been built. Until it is, this page describes mechanisms and their tests, not an effect.
