TRANSMISSION 050

A Skill Is
a Dated Source

Every reusable procedure is written once, as a single file, kept in exactly one canonical location. The tools that read it — several different kinds of coding agents — reach that one copy through a link placed by the operator's hand; none is handed its own separate copy to drift out of sync.

November 2026·Field note·Procedure·5 min read
01

One copy, read by every hand

One canonical location; every tool reaches the same copy

Every reusable procedure is written once, as a single file, kept in exactly one canonical location.

Several different kinds of coding agents read it. They reach that one copy through a link placed by the operator's hand; none of them is ever handed its own separate copy to drift out of sync.

02

Short enough to stand alone

A fixed, short format

The format is deliberately small: a fixed, short set of header fields, a one-sentence description, and a body capped at a modest line limit.

The description is written so its first sentence alone — under 60 characters — is enough to understand what the skill does without opening the file. One of the tools that reads these files truncates long descriptions, so the short form has to carry the whole meaning on its own.

03

A collision keeps both versions

Checked before it is added

Registering a new or changed skill is checked before it's added.

If a name collision arrives with genuinely different content, the system keeps both — the new one lands under a version-suffixed name rather than silently overwriting the old one. Nothing is ever replaced without a trace of what it replaced.

Remembered habit versus registered skill

A remembered habit

Lives only in one session. Vanishes when it ends. Can silently drift between agents.

  1. 01FormedA procedure works once; the session remembers it.SESSION
  2. 02DriftsThe next hand learns it by word of mouth; details change.BLIND
  3. 03FailsTwo agents follow two versions; nothing can be traced.UNTRACED

A registered skill

One file. One version history. The same copy read by every tool.

  1. 01WrittenFixed, small format; one canonical location.OK
  2. 02CheckedCollision and credential-slot checks pass before registration.OK
  3. 03LinkedOne link into every tool that reads it; no copies.OK
  4. 04KeptA changed version lands under a new name; the old one stays.OK
Nothing is ever replaced without a trace of what it replaced. A collision keeps both versions.

Checked before registering; nothing is replaced without a trace.

04

Found by what it does, not where it lives

Found by description, not by path

Skills are not found by memorizing where they live; they're found by searching what they do, over their description text.

A vector index is available when asked. As of the most recent count there were seven registered.

A credential check before registration

A skill that declares it needs a credential to run is registered only once a live check confirms every one of its declared credential slots is present — and the registration index itself never reads the credential's value, only whether the slot exists.

What a skill is not allowed to carry

Declared needs, checked once, never read by the index
