TRANSMISSION 025

The Homepage
Learned to Pulse

In June 2026 the first screen of the site gained a console that explained how a request becomes a governed run. This revision reads that console against the code and the tests, says where it lives today, and separates a diagram that moves from a reading that measures.

June 2026, revised November 2026·Interface proof·Release note·9 min read
Dated. This note describes the homepage code and tests in the site repository as of 10 November 2026. The June release is described as the code shows it. The live domain was not checked for this revision.
Revised 10 November 2026. The original called the console the site’s first screen. That is no longer true: since July the root serves a different homepage. The note now says where the console lives, what each of its words is backed by, what the test suite does and does not pin, and describes the later public witness reading. Interactive panels were added. The campaign packet is kept, in its own block at the end.
Correction, 10 November 2026. The June text said "The first screen of UnwindCode.ai now does more than state a thesis." Since the 19 July 2026 change the root domain serves the lab homepage, and the pulse console remains at the /home route. The page also said the new test suite "checks the hero console, schema, bilingual copy, metadata, asset safety, and discovery files". It does. It also still pins a stat of 32 public transmissions on that console, while the registry now lists 46 entries (45 numbered, plus a second page that carries number 27). That figure is stale and is flagged under section 05.
01

A diagram in words

What the June console was

The June release did three things on the homepage of that time. It placed a console beside the hero text with four numbered steps: signal, cortex, memory, proof. It added one boundary line stating that money, files, public posts and Web3 broadcast stay approval-gated. And it added a textless graphic, the Organism Pulse Field, a small SVG that animates with CSS.

The first thing to say about "pulse" is what it meant. The motion is decorative: a lightweight SVG and CSS animation with a reduced-motion rule inside the asset itself, no JavaScript and no data. The words are static copy, translated into Spanish under their own keys. Nothing in that console measured anything. It did not trace a real request through a real cortex. It was a diagram of an intended run, and the asset manifest says so in its own purpose line: it exists to make the hero explain how a visitor signal becomes a governed organism run.

That is a legitimate thing for a diagram to be, and the June note was right to keep the meaning in readable HTML rather than inside the image. The problem is only the title. A homepage that learned to pulse sounds like a homepage that reads a pulse. In June it did not. The explorer below goes through each word on the console and names what, in the code and registries, actually stands behind it.

02

What shipped, as the code shows it

Checked on 10 November 2026

The panel below filters the June release by what can be checked. Cards marked "Shipped" are files you can open and tests you can run. Cards marked "Copy" are text. The card marked "Stale" is a figure that was right once.

Four details are exact as of today. The pulse graphic is 8,171 bytes, about half of the 16 kilobyte target the manifest sets for it. The manifest entry has status production and a review date of 5 June 2026. The graphic is loaded with empty alt text and is hidden from assistive technology, because the meaning is in the ordered list next to it, which carries its own label. And the English and Spanish copy sit under the same set of keys.

One property of this list matters beyond the pulse. A test that pins a literal is a trap in both directions: it protects the page from accidental edits and it keeps a stale number alive. The fix is not to remove the test. It is to decide which numbers on a page are copy that a person updates, and which should be computed from the registry. This note does not make that change. It flags it.

03

Where the pulse lives now

From the repository history

Where the console sits today is a story about publication, not design, and the repository history tells it in dated steps. The June note is dated 5 June 2026 and the asset manifest was reviewed that day. In the repository, the pulse graphic first appears in a commit dated 15 June, on a branch.

According to the 3 July merge message, the new version was built on a branch on 15 June and never merged, so each deploy from the main line since then had kept shipping the older homepage until that merge restored it. That is the same class of failure that Transmission 31 describes: a thing exists and is correct, and the public body is a different one. The timeline below follows the console from there.

04

The pulse that measures

A real reading, with rules for failing

The lab homepage that replaced the console on the root carries something the June console did not: a reading. It shows one line from a public witness on the Internet Computer: the age of the most recent beat from one named organ, and the total number of beats counted. The code that does it is short and its rules are the interesting part.

The panel runs them. Scenarios are the cases the test suite covers: a new beat, the same beat again, a stalled endpoint, a malformed reply, a hidden tab. The left column is a pulse that animates whatever happens. The right column is the witness, step by step. The rules come down to one idea, that unknown is not zero. When the reading fails, the numbers are erased and the line says it cannot verify. It never shows the last number as if it were current, and it never shows zero.
