TRANSMISSION 029

The Agent-Readable
Organism

A site can be readable to machines without handing them anything to act with. This note says exactly what unwindcode.ai ships for agents on 10 November 2026: a guide file, a services manifest, five registries and eight read-only routes that retrieve evidence and never write an answer. Everything else is labelled design, plan or metaphor.

June 2026·Rewritten 10 November 2026·Public interface layer·10 min read

Dated note. This note describes the public machine-readable surface of unwindcode.ai as it exists in the site's source on 10 November 2026. It was first written on 14 June 2026. It was rewritten from the shipped files and their tests; the live site was not called while writing, so what is said about the live site is what the source says it does.

01

Every claim, with its trail

The thesis is an opinion · the rest is a ledger

The next web interface is not a page. It is a contract an agent can inspect. That is a design stance and the only opinion in this note; everything after it is a statement about files.

Agent-readable design is an architectural discipline, not search-engine optimisation with new vocabulary. A person tolerates atmosphere and missing coordinates. A machine needs stable routes, explicit scopes, source references, a review status and stated limits; without them it turns narrative into inference.

Below is every claim this note makes, tagged as shipped (a file or route you can read, with a test), design (an intent), plan (not built), metaphor (language only) or removed (taken out in this revision). Filter by kind and open a card for its trail.

The trail rule

A statement with no file, test or dated record behind it is either labelled as a design intent or deleted. Counts on this page are counts of the source on 10 November 2026, not of anything running.

02

Eight things an agent can read

The component explorer · from the source, 10 November 2026

There is no hidden machinery behind the word “organism” here. The machine-readable surface is three plain files, five static data files and a handful of serverless routes that read those data files. Select a component to see what it does, what it takes and which file and test stand behind it.

Seven of the eight read routes sit behind a rate limiter; the status route does not. In production, if the limiter's store is not configured the routes answer with a refusal instead of serving unmetered. Whether it is configured on the live site could not be checked from the record, so this note makes no claim about it.

03

What a request gets back

A model of the documented behaviour · not a live call

Retrieval is not authority. The search route and the grounding route take the same parameters and answer in two shapes: search returns ranked evidence excerpts, grounding returns a packet that lists what must be shown and refused before anyone writes an answer. Neither composes one. Pick a request to see how each route handles it, as the code and its tests describe.

      A model, written from the route code and its tests. It does not call the site.

      The no-answer behaviour is enforced by absence: the packet's policy says synthesis is not allowed, and no route in the manifest generates an answer from it. If an answer route is ever added, the packet already names four steps it must take first: render the citations, render the claim qualifications, enforce the five refusal rules and review the answer route's own behaviour. That is a place the code reserves for a design, not a feature.

      04

      The contract sketch, and where it is real

      An illustration of intent · not a published file

      The first version of this note printed a small JSON contract for the site. It was an illustration. No such file is published, and the correction above says so. Its fields are still a useful checklist: for each one, the panel below says where the idea is real today, where it is only prose, and where it does not exist.

      The Agent Contract Protocol is the working method for page and route authors: declare what a page is, expose public-safe metadata, retrieve evidence, ground it with citations and qualifications, ask before anything consequential, cite the source and record the result. It is a design: a checklist this note was written to follow, not a program. Retrieve, ground and cite have code behind them; ask and record rest on review by a person.

      Three hazards motivate it, and they are named as hazards, not as incidents. Context laundering is private memory leaking into a public answer without a source: the read routes load only committed public data files, and the grounding packet states that private prompts and runtime evidence are excluded. Stale authority is an old proof read as current: it is why every figure here carries a date. Hidden privilege is a tool implying a permission: the eight read routes accept only read methods and answer anything else with a refusal.

      06

      What this note does not claim

      Not done, on purpose · plan, not built

      Agent-readable does not mean agent-authorized. This is a Manual Brain Mode transmission: a person-governed hand wrote it from the record, and it is not evidence that the Brain publishes, posts, signs, spends or contacts anyone by itself. Nothing here says an agent relies on these files; no record of who calls the routes was read. The statements about read-only behaviour cover the eight read routes only: the source also holds other server routes that are not in the manifest, and this note makes no claim about them.

      The guide file's list names 34 transmission routes (21 to 24 and 26 to 55) while the registry holds 56 entries, so the list can drift from the archive. Whether it should name every transmission is the operator's decision.

      Next-cell memory. The Agent Readiness Cell is a plan, not built, as of 10 November 2026. As designed it would be a read-only reviewer: it would scan the public routes, the guide file, the manifest, the registries and the claim language, and write a private report before any new transmission is recommended. The closest thing that exists is a manual parity script that compares the local sources with the live site and smoke-tests search, grounding and status; it checks, it does not review. Posting assets for this transmission remain internal creator material and do not appear on public pages.
