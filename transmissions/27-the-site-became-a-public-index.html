Transmission 027

The Site Became a Public Index

The local website work is not just another page. It turns UnwindCode.ai into a public-safe retrieval surface: registries, search, grounding packets, claims, assets, and disabled-answer boundaries.

June 2026Public ProofRetrieval Surface
01 / Local signal

A website can become a memory surface without becoming an answer engine.

The unpushed website work adds public registries and read-only APIs for assets, architecture, claims, organisms, transmissions, search, grounding, status, and subscriptions. The important move is restraint: retrieval is allowed, but unchecked answer authority is not.

The site is learning to expose public evidence without dragging private runtime notes, owner manifests, credentials, or hidden procedures into the browser.

02 / Route map

The public site now has organs for retrieval.

Each route has a narrow job. The site does not need one omnipotent endpoint. It needs small public surfaces that can be inspected, cached, rate-limited, and refused when the context is unsafe.

/api/searchLexical registry retrieval with answer generation disabled.
/api/groundingTop-source packet for future grounded answers without synthesis authority.
/api/claimsClaim labels, evidence status, risk levels, and citation boundaries.
/api/assetsAsset provenance and approval status without posting authority.
/api/statusAggregate public metadata, not private runtime truth.
03 / Grounding flow

Search retrieves. Grounding frames. The answer still has to earn permission.

04

06 / Social packet

The public index has a four-frame proof packet.

Creator approval is required before publishing. This packet does not authorize production deployment, public posting, paid media, Web3 action, or unreviewed answer generation.
