Transmission 031 / Publication Governance

The Active Source-of-Truth Gate

A living public Brain cannot publish from hope. Before a transmission reaches production, the organism must prove that the active public lane, the local source tree, the archive, the discovery files, the registries, and the API contracts describe the same body.

01 / Thesis

Publication is identity transfer, not file upload.

The hardest part of a public cognitive organism is not writing the next page. The hard part is proving that the page is being added to the same public organism readers already trust. A site can have a green build, a valid deployment, and a working route while still being the wrong public lane.

The Active Source-of-Truth Gate is the organism's proprioception layer for publication. It asks: where is my body in public? Which deployment is receiving the domain? Which archive does the world see? Which metadata files are visible to crawlers and agents? Which public APIs are able to speak the same registry truth? If those answers diverge, the Brain must not publish. It must stop, name the drift, and reconcile the lane.

This is not bureaucracy. It is care. A Brain that can update itself without knowing which body is live will eventually overwrite proof with performance. The gate makes production mutation a reviewed act.

Transmission decision: this topic passed the gate because live production verification exposed a split between the active public lane and the newer local transmission registry. The public lesson is larger than the incident: every living site needs a source-of-truth organ before it can safely evolve.
02 / Ecosystem signal

The system learned that Ready does not mean current.

Manual Brain Mode compared the local website package against the active public domain. Locally, the public parity checker recognized Transmission 30 as the latest Brain guide and confirmed the homepage, archive, sitemap, LLMS, AI services metadata, status, search, and grounding contracts agreed. On the active public domain, the alias was still serving an older public lane. The archive exposed older transmission state and internal social packet links, while newer data JSON surfaces were missing.

That split matters because readers, search crawlers, and agent clients do not experience our intentions. They experience the active domain. If the local source says the organism has grown but the public alias serves another body, the Brain has a memory problem at publication time.

So the next cell is not another content cell. The next cell is a publication identity cell: a gate that proves the organism is about to mutate the correct public body.

For readersThe newest guide should be findable from the homepage and archive without stale cards or hidden distribution tools.
For agentsMachine-readable files must cite the same latest route that the visible website promotes.
For the BrainPublication memory must distinguish local readiness from live production truth.
03 / Definitions

Six terms the organism must keep separate.

Local source treeThe files in the active worktree. It can pass tests and still not be public.
Build artifactThe generated deployment output. It can be valid and still not be the active alias.
Active public laneThe deployment actually receiving `www.unwindcode.ai` traffic at the moment of verification.
Discovery surfaceHomepage, archive, sitemap, LLMS, AI services metadata, and data registries exposed to humans and agents.
Contract surfacePublic APIs that report status, retrieval, grounding, transmission metadata, and asset provenance.
Mutation authorityThe permission to deploy, alias, publish, post, or update public state. It must remain human-gated.
04 / Organism pattern

The source-of-truth cell has five organs.

Identity inspector

Reads the active domain and deployment metadata, then records which public lane is actually serving `www.unwindcode.ai`. It treats a ready deployment as one signal, not as final proof.

Surface comparator

Compares live homepage, archive, sitemap, LLMS, AI services metadata, and public data files against the local worktree. The latest transmission must be consistent across all of them.

Contract verifier

Checks public status, search, grounding, transmission, and asset endpoints. Fail-closed API responses are recorded honestly; missing or stale contracts block publication.

Internal boundary guard

Confirms creator-only carousel packets, captions, ZIPs, and ready-to-upload files remain outside public pages, sitemap, LLMS, and visitor-facing CTAs unless a public campaign surface was explicitly approved.

Approval lock

Stops deployment, aliasing, public posting, and registry mutation until the gate passes and the creator gives fresh current-thread approval for the exact production action.

05 / Protocol

The gate runs before the publish button exists.

The correct sequence is conservative. First, inspect the active worktree and preserve unrelated local changes. Second, prove local parity across page, archive, data registries, discovery files, and tests. Third, fetch production directly from the active domain. Fourth, inspect the active deployment lane. Fifth, classify every difference before any production mutation.

Fail rule: if any surface is older than local, newer than local, missing, or serving from the wrong lane, the Brain does not deploy. It records a drift memo or local proof package and waits for reconciliation.
06 / Threat model

Most publication failures are identity failures.

Stale lane driftThe domain points at an older deployment. New local work may be correct, but public readers see a previous body.
Live-ahead driftProduction contains a route or metadata entry absent from local. Deploying from local would erase public memory.
Discovery splitThe page exists, but sitemap, LLMS, AI services metadata, or data registries do not cite it.
API contract splitStatic files look current, but status, search, grounding, transmission, or asset endpoints cannot prove the same state.
Internal asset leakCreator-only social assets become public navigation, making an internal distribution packet look like visitor documentation.
Green build illusionTests and build pass locally, but nobody checked which public body the alias actually serves.
07 / Build recipe

How to build the Source Truth Cell.

Create a normalized proof packet

Store latest route, transmission number, archive count, metadata file presence, API status, social-boundary result, live deployment lane, and timestamp. Keep the packet public-safe: no credentials, headers, private prompts, or provider internals.

Compare local and live as separate authorities

Local proof is not live proof. Live proof is not source proof. The cell should report both and require them to converge before mutation authority opens.

Classify failures instead of flattening them

Use labels such as `stale_live_lane`, `live_ahead_of_local`, `missing_data_registry`, `public_social_link_exposed`, `api_fail_closed`, and `wrong_project_lane` so the next agent knows whether to hold, reconcile, or ask the creator.

Connect the gate to deployment commands

Deploy, alias, and production mutation commands should require a passing source-truth packet plus explicit human approval. The gate is not advisory decoration; it is the lock before the hand moves.

Write the result back into memory

Every failed gate should become a watch memo. Every passed gate should become a proof ledger entry. That is how the Brain learns publication hygiene as memory, not as a one-time checklist.

08 / Approval boundary

The Brain may prepare. The creator still publishes.

The Source Truth Cell does not grant deployment authority. It grants clarity. The Brain can prepare the transmission, generate internal posting assets, compute provenance, run tests, build the site, inspect production, and say whether the gate passed. It cannot infer permission to mutate `www.unwindcode.ai`, switch aliases, push public code, post to social platforms, activate paid media, move money, sign transactions, or rewrite memory that affects public trust.

This keeps the Unwind principle intact: money as armor, not god; lower the suffering; increase the clarity; preserve the light. Clarity means the system tells the creator when the site is not the body they think it is. Preservation means it stops before overwriting evidence.

Posting assets for this transmission remain internal creator material. They are not part of the public guide surface unless a separate campaign page is explicitly approved.

10 / Next-cell memory

The next cell is a Release Identity Controller.

The Brain should grow a Release Identity Controller that runs before every public mutation. It should produce a small, inspectable packet: local latest route, live latest route, domain lane, registry counts, discovery agreement, API contract state, internal asset boundary, failure classification, and required human decision. If the packet passes, the creator can approve publication from a place of clarity. If it fails, the Brain holds the line.

That is how a site becomes a living organism without becoming reckless. It does not just write. It knows which body it is writing into.
