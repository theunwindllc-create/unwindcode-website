# Asset Creative Briefs — proof without decorative overclaim

## Decision

No new image, video, logo, illustration, or generated media is required for this repair. The current ledger's table, pills, and source text are the right assets. Introducing a glowing chain, seal, or lock would visually assert authentication the present raw read does not establish.

## Minimal UI asset brief

If a small state mark is needed, use existing type and CSS tokens from `proof/ledger/index.html`: muted violet or amber border with the literal text **“Response unverified”**. Use a separate age label for a reported beat. Keep the status fully readable without color or motion. Do not use a green certification check until live verified-host evidence exists.

If a diagram is later useful, show three distinct boxes: `First Body report → canister update → HTTP response to browser`, with the last arrow explicitly marked `raw / not certificate-checked` today. A future version may change only that arrow to `gateway certificate-checked` after proof. The diagram must not imply the head's underlying truth or append-only history is certified.

## Rights and provenance

Reuse existing local CSS and typography. Do not add third-party screenshots, badges, or ICP endorsement marks to public assets without source and rights review. The [ICP response-certification guide](https://docs.internetcomputer.org/guides/frontends/certification/) is a citation for mechanics, not a co-signature of this implementation.
