Capability ledger

What the mirror can do, what it cannot claim, and where proof lives.

Before the experience becomes emotional, the product path names the actual system boundaries: input, output, memory, tool authority, approval, and proof. Reflection is allowed to clarify; it is not allowed to become hidden judgment.

  1. 01 / Capture

    Turn a human signal into a state packet.

    The mirror can receive current state, pressure, intention, friction, and language from the user without forcing it into a productivity category.

    Input
    Current state, emotional context, desire, friction, and optional prior loop.
    Output
    A readable state packet the user can accept, edit, or refuse.
    Blocked claim
    No diagnosis, identity verdict, hidden profiling, or destiny claim.
    Proof route
    Inspect the session console
  2. 02 / Memory

    Use reviewed continuity without turning memory into authority.

    Pattern memory can help reflection avoid starting from zero, but remembered material must stay inspectable, reversible, and subordinate to the person.

    Memory boundary
    Only user-reviewed continuity should inform future loops.
    Output
    A pattern hypothesis with uncertainty preserved.
    Blocked claim
    No hidden memory map, identity inference, or irreversible profile.
    Proof route
    Follow the reflection loop
  3. 03 / Motion

    Suggest one reversible next action.

    The mirror can convert insight into a small step, proof question, repair, or boundary the user chooses. Motion stays human-owned.

    Tool boundary
    No public contact, posting, spending, file writes, or reputation motion.
    Output
    One next action with a stop condition and proof expectation.
    Blocked claim
    No automatic life decision, public action, or external consequence.
    Proof route
    Read the product proof
  4. 04 / Stop

    Escalate back to human care when the boundary appears.

    A trustworthy mirror must know when not to be the answer. If the request touches safety, diagnosis, crisis, or professional support, the product posture becomes handoff.

    Approval boundary
    Care, crisis, identity, and professional decisions remain outside automation.
    Output
    A human-led support or review path, not a machine verdict.
    Blocked claim
    No therapy replacement, emergency handling, or professional advice claim.
    Proof route
    Inspect the authority gate
